On ne peut pas piloter ce qu'on ne sait pas nommer. Ces 9 mots reviennent dans toutes les discussions sur l'IA — réunions, articles, démos commerciales. Une fois qu'ils sont clairs, le reste du sujet devient étonnamment accessible. Cliquez sur une carte pour révéler sa définition.

01

IA générative

Définition

// 01 — IA GÉNÉRATIVE

Famille d'IA capables de créer du contenu original — texte, image, code, audio, vidéo. Là où une IA classique trie (spam ou pas spam ?), l'IA générative produit du neuf, un peu comme un musicien qui improvise après avoir écouté des milliers de morceaux.

02

LLM

Large Language Model

Définition

// 02 — LLM

Le « moteur » derrière les assistants comme ChatGPT, Claude ou Gemini. Il devine le mot le plus probable… mais ne « sait » rien au sens humain.

⚠ À ne pas confondre avec « l'IA » en général : le LLM n'est qu'une brique. Branché à des outils, il devient un agent ; seul, il ne fait que produire du texte.

03

Agent

Définition

// 03 — AGENT

Si le LLM est le cerveau, l'agent est le collaborateur complet : et va agir seul — planifier, se servir d'outils, naviguer sur le web, lire des fichiers, déclencher des actions.

⚠ À ne pas confondre avec un chatbot : un chatbot répond. Un agent agit — il enchaîne des étapes et utilise des outils pour atteindre un but.

04

MCP

Model Context Protocol

Définition

// 04 — MCP

Standard ouvert qui permet à un agent de se connecter à vos outils et données (CRM, fichiers, API maison…). Une sorte de « prise universelle » entre l'IA et vos systèmes.

05

System prompt

Fichier d'instruction

Définition

// 05 — SYSTEM PROMPT

Document qui définit le rôle, le ton, les règles et le périmètre d'un agent. C'est sa « fiche de poste » : il ne change pas le modèle, il cadre son comportement.

06

Skill

Définition

// 06 — SKILL

Compétence modulaire ajoutée à un agent pour lui donner un savoir-faire précis (générer un PDF, analyser un Excel, suivre une charte rédactionnelle).

⚠ À ne pas confondre avec le system prompt : le system prompt dit qui est l'agent ; un skill lui ajoute un savoir-faire concret.

07

Token

Définition

// 07 — TOKEN

La plus petite « brique » de texte lue par un LLM — environ ¾ d'un mot en français. C'est l'unité qui sert à compter la facturation et la « mémoire » du modèle. Exemple : « intelligence » pèse à lui seul 3 à 4 tokens. Plus une conversation est longue, plus elle consomme de tokens.

08

RAG

Retrieval-Augmented Generation

Définition

// 08 — RAG

Technique qui permet à un LLM d'aller chercher l'information dans vos documents avant de répondre, au lieu de puiser uniquement dans sa mémoire d'entraînement. Concrètement : il cite vos sources plutôt que d'inventer. C'est la réponse la plus directe au problème des hallucinations.

⚠ À ne pas confondre avec le fine-tuning : le RAG consulte vos données à chaque question ; le fine-tuning, lui, réentraîne le modèle.

09

Fine-tuning

Définition

// 09 — FINE-TUNING

Réentraînement d'un modèle sur vos propres exemples pour qu'il adopte durablement un style, un format ou un domaine précis. Plus lourd et plus coûteux que le RAG, et réservé aux cas où l'on veut modifier le comportement du modèle en profondeur — pas juste lui donner accès à des données.

Le marché compte des centaines d'outils et bouge chaque semaine. Lequel correspond à votre usage ? Et faut-il l'utiliser tel quel, ou développer une solution sur mesure ? C'est précisément là que j'interviens.

Je ne mise pas sur un outil, je mise sur une méthode de choix — pour que votre environnement survive aux effets de mode. Quel modèle, quel framework, quel niveau d'autonomie : je vous aide à arbitrer en fonction de votre contexte, pas des tendances.

Je développe vos agents sur mesure

Au-delà du conseil, je conçois et développe des agents adaptés à votre contexte. Mon environnement de prédilection s'appuie sur Claude comme moteur de raisonnement, pour sa fiabilité sur les tâches longues et structurées, et sur des outils comme GitHub Copilot et Claude Code pour un développement rapide et maîtrisé. Un choix assumé de qualité et de robustesse plutôt que de course aux fonctionnalités.

Le bon outil n'est qu'un début — la vraie valeur vient de ce qu'on en fait.

Un prompt, c'est simplement la consigne que vous donnez à l'IA: Un prompt flou donne une réponse moyenne, un prompt soigné donne un résultat exploitable. Le prompting est la compétence la plus rentable à acquérir !
Maîtriser les bases suffit pour 80 % des usages ; les 20 % restants — fiabilité, reproductibilité, intégration dans un système — relèvent d'un autre métier.

Le même besoin, deux consignes

❌ « Écris un mail pour relancer un client. »
✅ « Tu es commercial·e B2B. Rédige un mail de relance court et chaleureux à un client qui n'a pas répondu à mon devis depuis 10 jours. Ton : professionnel mais humain. Termine par une question ouverte. »

// TECHNIQUES COURANTES

  • Zero-shot on demande directement, sans exemple — suffisant pour les tâches simples et bien définies.
  • Few-shot on montre 2-3 exemples du résultat voulu — idéal pour imposer un format précis (ex. : classer des avis clients toujours de la même façon).
  • Chain-of-thought on demande de raisonner étape par étape — utile sur les tâches logiques ou les calculs, où une réponse directe se trompe souvent.
  • Prompt structuré balises XML ou Markdown pour découper l'instruction — indispensable dès qu'un prompt devient long ou doit être réutilisé.
  • Itération raffiner progressivement plutôt que tout demander d'un coup — souvent plus rapide que de chercher le prompt parfait du premier coup.

Le niveau au-dessus

Au-delà du prompt isolé, un agent fiable repose sur des techniques moins visibles : gérer le contexte (que mettre, que retirer pour ne pas noyer le modèle), structurer les instructions pour qu'elles tiennent dans la durée, et tester systématiquement plutôt que de se fier à une impression. C'est là que se joue la différence entre un prompt qui marche une fois et un système qui tient en production.

Enjeux et limites à connaître

Les LLM peuvent halluciner (inventer des faits avec aplomb), reproduire des biais présents dans leurs données d'entraînement (genre, culture, idéologie), être sensibles à la formulation (un mot change la réponse), et leurs connaissances ont une date de coupure. Surtout, ils ne « comprennent » pas comme nous : là où un cerveau humain s'appuie sur le sens, le corps et l'expérience, un LLM prédit statistiquement la suite la plus plausible. Garder cette distinction en tête, c'est déjà éviter 80 % des mauvaises surprises.

Imaginez devoir confier à une seule personne la compta, le SAV, la veille concurrentielle et la rédaction de vos posts. Elle ferait tout… moyennement. L'approche moderne est différente : une équipe d'agents spécialisés, chacun avec un rôle précis, ses compétences et ses outils dédiés. Comme une vraie équipe, mais disponible 24h/24.

Quand un agent n'est pas la solution

Un agent n'est pas toujours la bonne réponse. Pour une tâche ponctuelle, un simple prompt suffit. Pour un processus 100 % déterministe (toujours les mêmes règles, sans jugement), un script classique est plus fiable et moins cher. Je le dis avant de commencer : déployer un agent là où il n'apporte rien, c'est de la complexité pour rien.

Je vous accompagne pour identifier les bons cas d'usage, concevoir vos agents et les déployer progressivement, sans bouleverser vos processus existants.

Un agent qui impressionne en démo et un agent qui tient en production, ce ne sont pas les mêmes. La différence se joue sur la méthode. Je l'aborde avec la rigueur d'un protocole de recherche : une hypothèse, des étapes claires, des mesures à chaque palier. C'est ce qui évite le piège classique — un prototype séduisant qui s'effondre dès qu'il rencontre la réalité. Voici la démarche que j'applique pour passer de l'idée à un système qui dure.

Un agent n'est jamais « fini » : il vit avec votre activité et doit être maintenu.

C'est la section la plus technique — mais l'idée est simple. Un agent IA, par défaut, ne connaît que ce sur quoi il a été entraîné : il ignore tout de vos clients, vos produits, vos documents. Le MCP est la « prise universelle » qui le branche sur vos vraies données et vos outils internes — CRM, base produits, documents, API métier — sans dépendre d'intégrations propriétaires fermées. Résultat : un agent qui parle de votre activité, pas de généralités.

Concrètement, à quoi ça sert ?

Imaginez demander à votre agent, en langage naturel — « Quels clients n'ont pas recommandé depuis 6 mois ? » — et qu'il interroge directement votre vrai CRM pour répondre, avec les vrais noms et les vrais chiffres. Sans MCP, l'agent ne connaît que des généralités ; avec un MCP sur mesure, il travaille sur vos données.

// POURQUOI UN MCP SUR MESURE

Souveraineté

Vos données restent chez vous, vous contrôlez ce qui est exposé.

Précision métier

L'agent manipule vos vraies données, pas une approximation.

Réutilisabilité

Un même MCP sert plusieurs agents et plusieurs IA (Claude, ChatGPT…).

Évolutivité

On ajoute des fonctionnalités au fur et à mesure des besoins.

// MA DÉMARCHE

  1. Analyse de vos systèmes existants

  3. Développement & sécurisation du serveur MCP — contrôle fin des accès, lecture seule par défaut, journalisation des actions
  4. Intégration dans votre environnement IA
  5. Documentation & formation de vos équipes

Parlons-en : un MCP bien conçu transforme un agent générique en véritable collaborateur métier.
